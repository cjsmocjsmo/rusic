================================================================================
TIZEN DEVICE SUPPORT - FLAC TO MP3 TRANSCODING IMPLEMENTATION
================================================================================

OVERVIEW
--------
This document describes the implementation of Samsung Tizen device support for
the Rusic Svelte music player. The primary goal is to handle the limitation
that Samsung Tizen browsers do not support FLAC audio file playback.

The solution implements automatic detection of Tizen devices and seamless
transcoding of FLAC files to MP3 format on the backend, transparently to the
user experience.

PROBLEM STATEMENT
-----------------
- Samsung TV Tizen browsers cannot play FLAC audio files
- The music library contains many FLAC files that must be served to Tizen devices
- Current implementation serves FLAC files directly without format detection
- When a Tizen device requests a FLAC file, playback fails silently or with errors

SOLUTION ARCHITECTURE
---------------------
The solution uses a hybrid client-server approach:

1. CLIENT SIDE (Svelte Frontend)
   - Detect device type (Samsung Tizen vs standard browser)
   - Detect codec support (FLAC support in browser)
   - Signal backend about transcoding needs

2. SERVER SIDE (Backend - Separate Implementation)
   - Receive format requirement from client
   - Determine file format from request
   - Transcode FLAC to MP3 on-the-fly or serve cached version
   - Stream audio to client

FILES CREATED
=============

1. src/lib/tizenDetection.js (NEW)
   --------------------------------
   Purpose: Device and codec capability detection module
   
   Exported Functions:
   
   - isSamsungTizen() → boolean
     Checks User-Agent string for Tizen/Samsung/SmartTV patterns
     Detects if page is running on Samsung Tizen browser
   
   - supportsFlac() → boolean
     Creates audio element and tests FLAC support via canPlayType()
     Returns true if browser can play FLAC files
   
   - supportsMp3() → boolean
     Creates audio element and tests MP3 support via canPlayType()
     Returns true if browser can play MP3 files
   
   - hasTizenAPIs() → boolean
     Checks for Tizen-specific JavaScript APIs (window.tizen, window.webapis)
     Additional detection method for Tizen devices
   
   - needsAudioTranscoding() → boolean
     PRIMARY FUNCTION: Determines if MP3 transcoding is required
     Returns true if: (isTizen OR hasTizenAPIs) OR !supportsFlac()
   
   - getDeviceCapabilities() → Object
     Returns comprehensive device capability information:
     {
       isTizen: boolean,
       hasTizenAPIs: boolean,
       supportsFlac: boolean,
       supportsMp3: boolean,
       needsTranscoding: boolean,
       userAgent: string
     }

2. src/lib/audioRequestHelper.js (NEW)
   ----------------------------------
   Purpose: Audio URL building with format parameter injection
   
   Exported Functions:
   
   - buildAudioUrl(baseUrl) → string
     Takes a base audio URL (or file path)
     If transcoding is needed: appends "?format=mp3" or "&format=mp3"
     Returns the modified URL with format parameter
   
   - fetchAudio(url, options) → Promise<Response>
     Wraps standard fetch() with automatic format parameter addition
     Used for API calls that fetch audio data
   
   - buildAudioSrc(baseSrc) → string
     Builds audio src attribute for HTML5 audio element
     Applies format parameter based on device needs
     Used when setting audio.src directly

USAGE EXAMPLES:
   
   // Before (direct URL)
   audio.src = "http://backend/audio/song123.flac";
   
   // After (with format parameter on Tizen)
   const src = buildAudioSrc("http://backend/audio/song123.flac");
   // Result on Tizen: "http://backend/audio/song123.flac?format=mp3"
   // Result on standard browser: "http://backend/audio/song123.flac"
   audio.src = src;

HOW IT WORKS - REQUEST FLOW
================================================================================

PHASE 1-3: FRONTEND DETECTION & REQUEST MODIFICATION

1. APP INITIALIZATION
   ┌─ User opens Rusic web app on Samsung TV (Tizen browser)
   │
   └─ Browser loads +layout.svelte
      └─ onMount() executes
         └─ getDeviceCapabilities() runs
            ├─ isSamsungTizen() checks User-Agent → TRUE (Tizen)
            ├─ supportsFlac() checks codec support → FALSE
            ├─ hasTizenAPIs() checks for Tizen APIs → (might be TRUE)
            └─ needsTranscoding calculated → TRUE
      
      └─ Stores updated:
         ├─ deviceCapabilities.set({ isTizen: true, ... needsTranscoding: true })
         └─ needsAudioTranscoding.set(true)

2. USER PLAYS MUSIC
   ┌─ User clicks "Play" button on a song
   │
   └─ +page.svelte calls playsingle(src, rusicid)
      └─ sound2Store.js:playsingle() runs
         └─ Calls buildAudioSrc(src)
            ├─ Reads needsAudioTranscoding store → true
            └─ MODIFIES URL: "http://backend/audio/song.flac"
                            → "http://backend/audio/song.flac?format=mp3"
      
      └─ audio.src = modified URL
      └─ audio.play()

3. BACKEND RECEIVES REQUEST
   ┌─ Browser sends HTTP request:
   │  GET http://backend/audio/song.flac?format=mp3
   │
   └─ Backend sees format=mp3 parameter
      ├─ Parse query parameter: format = "mp3"
      ├─ Read file: song.flac
      ├─ Determine action:
      │  if file.endswith(".flac") AND format="mp3":
      │      → Transcode to MP3 (Phase 5)
      │      → Cache result (Phase 6)
      │      → Stream MP3 to client
      │  else:
      │      → Serve original file
      │
      └─ Send audio stream to browser

4. AUDIO PLAYBACK
   ┌─ Browser receives MP3 stream
   │
   └─ HTML5 audio element plays MP3
      └─ User hears music (no errors, smooth playback)

QUERY PARAMETER SPECIFICATION
==============================

The frontend now sends requests with this parameter structure:

Format: ?format={format_type}

Values:
  - "mp3"       : Request MP3 format (backend should transcode if needed)
  - undefined   : Request original format (no transcoding needed)
  
Examples:
  - http://backend/audio/song123?format=mp3
  - http://backend/audio/song123 (no format param means original)
  - http://backend/audio/song123?other_param=value&format=mp3

Backend Implementation:
  
  Python/Flask Example:
    @app.get('/audio/<file_id>')
    def serve_audio(file_id):
        format_requested = request.args.get('format', 'original')
        file_path = get_file_path(file_id)
        
        if format_requested == 'mp3' and file_path.endswith('.flac'):
            return transcode_to_mp3(file_path)
        else:
            return send_file(file_path)

DEVICE DETECTION DETAILS
========================

User-Agent Patterns for Tizen:
  - "Tizen" (case-insensitive)
  - "SAMSUNG" or "Samsung" or "SAMSUNG"
  - "SmartTV" or "smarttv"
  - "Smashtv"

Example Tizen User-Agents:
  - Mozilla/5.0 (SmartTV; Tizen 6.0) ...
  - Mozilla/5.0 (Linux; U; Tizen 2.0) ...
  - Mozilla/5.0 (Linux; Tizen 3.0) AppleWebKit/537.36 ...

Codec Detection:
  - Uses HTML5 audio.canPlayType() API
  - Returns "" if not supported
  - Returns "maybe" or "probably" if supported
  - Works in all modern browsers

Fallback Detection:
  - window.tizen (Tizen-specific JavaScript object)
  - window.webapis (Tizen WebAPIs)
  - If either exists, device is likely Tizen

PERFORMANCE CONSIDERATIONS
===========================

Frontend Impact (Minimal):
  - Detection runs once on app load: ~1-2ms
  - URL building happens per audio request: <1ms
  - Store updates: negligible
  - Total overhead: <10ms on app load, <1ms per request

Backend Impact (Significant):
  - FLAC decoding: 2-10 seconds per 3-minute song (quality dependent)
  - MP3 encoding: 1-5 seconds per 3-minute song
  - Total transcoding: 3-15 seconds (can be parallelized)
  - Cache helps dramatically (transcoding needed only once per file)
  - Recommend: async transcoding, background job queue

Storage Impact:
  - MP3 ~40% size of FLAC (smaller file size)
  - Cache directory grows with unique songs accessed on Tizen
  - Recommend: auto-cleanup of old cache files
  - Recommend: cache size limits and LRU eviction

SECURITY CONSIDERATIONS
=======================

No new security concerns introduced:
  - Query parameter "format" is harmless

Recommendations:
